# ADR 0004: Expose Memorable Through An MCP-First Agent Interface

Date: 2026-05-23
Status: Accepted

## Context

Memorable's primary users are agents. Agents need a stable way to initialize memory, write structured records, retrieve context, inspect provenance, review recent writes, correct mistakes, and generate human-readable views.

The product should not require each agent integration to import Memorable internals or know the details of Neo4j, Graphiti, or another storage adapter. It should also remain flexible enough to add a CLI or HTTP API later.

## Decision

Expose Memorable first as an MCP server over a reusable core library.

The intended shape is:

- core library: owns memory spaces, profiles, validation, provenance, temporal semantics, lifecycle operations, and retrieval contracts;
- MCP adapter: exposes those core capabilities as agent tools;
- future adapters: CLI or HTTP API can call the same core behavior later.

The MCP interface should include capabilities like:

- initialize or inspect a memory space;
- propose or update a memory profile;
- remember structured records;
- search memory;
- ask for current truth;
- ask for truth as of a time;
- inspect provenance;
- list recent writes;
- supersede, invalidate, correct, complete, reopen, or forget records;
- merge duplicates;
- generate human-readable views from memory.

Agents may write memory automatically when something crosses a clear threshold, subject to the project profile's write policy. Sensitive categories can require suggestion or confirmation.

## Consequences

Positive:

- Multiple agents can share the same memory system through a common protocol.
- Storage and implementation details stay behind Memorable's own core.
- CLI and HTTP interfaces can be added later without changing product semantics.
- Agent tools can stay focused on intentional memory operations instead of file manipulation or database details.

Negative:

- The MCP tool contract must be designed carefully because agents will depend on it.
- The core must not leak MCP-specific assumptions.
- Review and correction tools become part of the first-class surface, not optional extras.

## Guardrails

- MCP is the first interface, not the product model.
- Agent-facing tools should expose Memorable concepts, not raw storage details.
- Tool output should avoid repetitive provenance or certainty boilerplate unless it helps the user.
- Human-readable artifacts generated by tools are views of memory, not the canonical store.
